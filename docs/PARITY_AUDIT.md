## Android 연결에서 유지/확장된 부분

- WebView는 원본 HTML의 `file:///android_asset/index.html`을 직접 로드.
- `native-adapter.js`는 페이지 로드 후 주입하며, 원본 `index.html`을 변경하지 않음.
- 원본 JS 상태가 Android 재실행 후에도 남도록 저장/복원.
- Android 실제 권한 흐름: 사용정보 접근, 오버레이, 알림.
- 사용정보 접근이 허용되면 Android `UsageStatsManager`로 일일 앱 이용 시간을 얻음.
- 감시 서비스는 조건 OR, 자정 통과 시간대, 앱별 경고 순서, 무시 시 단계 증가, 사용 중단 시 초기화를 처리.
- 실제 외부 앱에서는 원본 경고 DOM/CSS를 별도 WebView 오버레이로 사용. 1단계 헤드업 알림은 시스템 Notification UI를 사용.

## 원본과 실제 Android 기능 간 남은 차이와 제약

1. 원본은 실제 패키지가 아닌 10개 **앱 범주**와 예시 분 단위 수치를 포함한다. 네이티브 구현은 일부 알려진 패키지만 범주에 매핑하므로 모든 설치 앱을 자동 식별하지는 못한다. 동일 앱의 숏폼과 일반 피드 시간을 분리하지 못할 수 있다.
2. 원본의 인사이트 주간 분포 및 순위 변화는 시연용 추정 계산이다. 실제 전체 과거 기록으로 바뀌지 않았고, 이를 측정 결과라고 주장하면 안 된다.
3. OS 헤드업 알림 디자인은 Android 시스템이 소유하므로 HTML 내부의 시연 패널과 픽셀 단위로 동일하지 않다. HTML 내부 경고 화면은 원본 그대로 유지된다.
4. 홈 화면 이동 명령, 포그라운드 감시 및 오버레이는 Android 버전/배터리 설정/백그라운드 실행 제한에 영향을 받을 수 있다. 기기에서 확인해야 한다.
5. HTML의 Google Fonts는 온라인 로드다. 오프라인에서는 폴백 폰트로 표시될 수 있다.
6. 강한 경고의 화면 흔들림·플래시도 원본 파일 그대로 남아 있다. 광과민 사용자에게 적합한지 안전성 검토가 필요하다.

## 2차 변경 소실 검토: 실제 앱 목록·실제 아이콘·권한 승인 체크

- 원본 `app/src/main/assets/index.html`은 변경하지 않음. 12개 화면, 55개 정적 버튼, CSS 24개 키프레임 그대로 유지
- `InstalledApps.java`: Android `PackageManager.queryIntentActivities(MAIN/LAUNCHER)`에서 **실제로 설치된 런처 앱** 목록 조회, 패키지별 `getApplicationIcon`을 PNG 데이터로 전달. 가상 이름/아이콘과 혼동하지 않음
- `native-adapter.js`: 원본 `const APPS` 배열 참조를 유지한 채 `splice`로 실제 앱 목록 갱신. 원본 캐러셀의 캐시 `fis`, 인디케이터, 선택 상태까지 갱신해 기존 클릭·스크롤 콜백을 그대로 실행. 홈·앱 추가·상세 화면은 이 데이터 사용
- Android `UsageEngine`과 `MonitorService`: 범주명이 아닌 실제 앱 패키지명을 기준으로 분 단위 사용시간과 경고 상태를 조회
- `WarningOverlay`: 외부 앱 경고 시 선택한 패키지명·아이콘을 원본 WebView 경고 화면에 주입
- 권한 화면: 원본 시연용 자동 체크 타이머만 네이티브 어댑터에서 대체. 세 항목의 실제 허용 여부 확인, 허용 시 320~620ms 후 원본 CSS 체크 애니메이션, 전체 허용·설치앱 로딩 완료 시 1.4초 후 진행. 하나라도 거부되면 자동 진입하지 않고 재요청 가능
- 앱 설정 이력이 있으면 권한 재승인 후 홈으로 복귀, 최초 실행이면 기존 앱 선택 화면으로 진행
